## 1. 项目结构规范

### 1.1 目录结构

```
APP/
├── pages/              # 页面目录
│   ├── index/         # 首页（菜谱列表）
│   ├── mine/          # 我的页面
│   ├── recipe/        # 菜谱相关页面
│   │   ├── detail/   # 菜谱详情
│   │   ├── edit/     # 菜谱编辑
│   │   └── list/     # 我的菜谱列表
│   ├── friend/        # 好友相关页面
│   │   ├── list/     # 好友列表
│   │   └── search/   # 搜索用户
│   └── favorite/      # 收藏列表
├── components/        # 自定义组件
├── cloudfunctions/    # 云函数
├── utils/            # 工具函数
├── assets/           # 静态资源（图片、图标等）
├── app.js            # 小程序入口文件
├── app.json          # 小程序配置文件
└── app.wxss          # 全局样式文件
```

### 1.2 文件命名规范

- **页面文件夹**：使用小写字母，多个单词用短横线连接，如 `recipe-detail`
- **组件文件夹**：使用小写字母，多个单词用短横线连接，如 `recipe-card`
- **云函数文件夹**：使用小写字母，如 `user`、`recipe`、`friend`
- **工具函数文件**：使用小写字母，多个单词用驼峰命名，如 `formatTime.js`
- **图片资源**：使用小写字母，多个单词用短横线连接，如 `icon-home.png`

### 1.3 页面和组件文件组成

每个页面或组件必须包含以下 4 个文件：
- `.js` - 逻辑文件
- `.wxml` - 模板文件
- `.wxss` - 样式文件
- `.json` - 配置文件

## 2. 代码风格规范

### 2.1 JavaScript 编码规范

#### 2.1.1 变量命名

- **常量**：使用全大写字母，多个单词用下划线连接
  ```javascript
  const MAX_IMAGE_COUNT = 5;
  const API_BASE_URL = 'https://api.example.com';
  ```

- **变量和函数**：使用小驼峰命名法
  ```javascript
  let recipeList = [];
  const userName = 'John';

  function getRecipeDetail(id) {
    // ...
  }
  ```

- **私有变量和方法**：使用下划线前缀
  ```javascript
  let _privateData = {};

  function _privateMethod() {
    // ...
  }
  ```

#### 2.1.2 函数定义

- **优先使用箭头函数**（除了需要 this 绑定的情况）
  ```javascript
  // 推荐
  const formatTime = (date) => {
    // ...
  };

  // 不推荐
  function formatTime(date) {
    // ...
  }
  ```

- **函数参数不超过 3 个**，超过时使用对象参数
  ```javascript
  // 推荐
  function createRecipe({ name, description, images, category }) {
    // ...
  }

  // 不推荐
  function createRecipe(name, description, images, category, taste, method) {
    // ...
  }
  ```

#### 2.1.3 异步处理

- **优先使用 async/await**，避免回调地狱
  ```javascript
  // 推荐
  async onLoad() {
    try {
      const recipe = await this.getRecipeDetail(this.data.recipeId);
      this.setData({ recipe });
    } catch (error) {
      wx.showToast({ title: '加载失败', icon: 'none' });
    }
  }

  // 不推荐
  onLoad() {
    this.getRecipeDetail(this.data.recipeId).then(recipe => {
      this.setData({ recipe });
    }).catch(error => {
      wx.showToast({ title: '加载失败', icon: 'none' });
    });
  }
  ```

- **必须处理异步错误**，使用 try-catch 包裹
  ```javascript
  async loadData() {
    try {
      const result = await wx.cloud.callFunction({
        name: 'getRecipeList'
      });
      return result.data;
    } catch (error) {
      console.error('加载数据失败:', error);
      wx.showToast({ title: '加载失败', icon: 'none' });
      return null;
    }
  }
  ```

#### 2.1.4 数据更新

- **使用 setData 时，只更新需要变化的数据**
  ```javascript
  // 推荐
  this.setData({
    'recipe.name': newName,
    'recipe.description': newDescription
  });

  // 不推荐（会导致整个 recipe 对象重新渲染）
  const recipe = this.data.recipe;
  recipe.name = newName;
  recipe.description = newDescription;
  this.setData({ recipe });
  ```

- **避免频繁调用 setData**，批量更新数据
  ```javascript
  // 推荐
  const updates = {
    name: newName,
    description: newDescription,
    images: newImages
  };
  this.setData(updates);

  // 不推荐
  this.setData({ name: newName });
  this.setData({ description: newDescription });
  this.setData({ images: newImages });
  ```

### 2.2 WXML 模板编写规范

#### 2.2.1 标签使用

- **语义化标签**：优先使用语义化的标签
  ```xml
  <!-- 推荐 -->
  <view class="container">
    <text class="title">{{recipe.name}}</text>
    <image class="cover" src="{{recipe.images[0]}}" />
  </view>

  <!-- 不推荐 -->
  <view class="container">
    <view class="title">{{recipe.name}}</view>
    <view class="cover" style="background-image: url({{recipe.images[0]}})"></view>
  </view>
  ```

- **避免过深的嵌套**：页面层级不要嵌套过深（建议不超过 5 层）
  ```xml
  <!-- 推荐：使用精简的方式实现 -->
  <view class="recipe-card">
    <image class="cover" src="{{item.images[0]}}" />
    <view class="info">
      <text class="name">{{item.name}}</text>
      <text class="author">{{item.authorName}}</text>
    </view>
  </view>

  <!-- 不推荐：嵌套过深 -->
  <view class="recipe-card">
    <view class="cover-wrapper">
      <view class="cover-inner">
        <image class="cover" src="{{item.images[0]}}" />
      </view>
    </view>
    <view class="info-wrapper">
      <view class="info-inner">
        <view class="name-wrapper">
          <text class="name">{{item.name}}</text>
        </view>
      </view>
    </view>
  </view>
  ```

#### 2.2.2 条件渲染

- **使用 wx:if 和 wx:else**，避免使用 hidden（除非需要频繁切换）
  ```xml
  <!-- 推荐 -->
  <view wx:if="{{recipeList.length > 0}}">
    <view wx:for="{{recipeList}}" wx:key="id">{{item.name}}</view>
  </view>
  <view wx:else class="empty">暂无菜谱</view>

  <!-- 不推荐 -->
  <view hidden="{{recipeList.length === 0}}">
    <view wx:for="{{recipeList}}" wx:key="id">{{item.name}}</view>
  </view>
  <view hidden="{{recipeList.length > 0}}" class="empty">暂无菜谱</view>
  ```

#### 2.2.3 列表渲染

- **必须指定 wx:key**，提高渲染性能
  ```xml
  <!-- 推荐 -->
  <view wx:for="{{recipeList}}" wx:key="id">
    {{item.name}}
  </view>

  <!-- 不推荐 -->
  <view wx:for="{{recipeList}}">
    {{item.name}}
  </view>
  ```

### 2.3 WXSS 样式编写规范

#### 2.3.1 选择器使用

- **优先使用 class 选择器**，避免使用 id 和标签选择器
  ```css
  /* 推荐 */
  .recipe-card {
    background-color: var(--card-bg);
  }

  /* 不推荐 */
  #recipe-card {
    background-color: #FFFFFF;
  }

  view {
    background-color: #FFFFFF;
  }
  ```

- **使用 BEM 命名规范**（Block-Element-Modifier）
  ```css
  /* Block */
  .recipe-card { }

  /* Element */
  .recipe-card__cover { }
  .recipe-card__title { }
  .recipe-card__author { }

  /* Modifier */
  .recipe-card--featured { }
  .recipe-card__title--large { }
  ```

#### 2.3.2 CSS 变量使用

- **必须使用 CSS 变量**，不要硬编码颜色、字号、间距等
  ```css
  /* 推荐 */
  .title {
    color: var(--text-main);
    font-size: 34rpx;
    margin-bottom: var(--spacing-md);
  }

  /* 不推荐 */
  .title {
    color: #333333;
    font-size: 34rpx;
    margin-bottom: 24rpx;
  }
  ```

- **常用 CSS 变量参考**（定义在 app.wxss）：
  - 颜色：`--color-primary`、`--text-main`、`--bg-color` 等
  - 圆角：`--radius-lg`、`--radius-base`、`--radius-sm` 等
  - 阴影：`--shadow-level-1`、`--shadow-level-2` 等
  - 间距：`--spacing-xs`、`--spacing-sm`、`--spacing-md` 等

#### 2.3.3 样式组织

- **按功能分组**，添加注释分隔
  ```css
  /* 布局 */
  .container {
    padding: var(--spacing-md);
  }

  /* 卡片样式 */
  .recipe-card {
    background-color: var(--card-bg);
    border-radius: var(--radius-lg);
  }

  /* 文字样式 */
  .title {
    color: var(--text-main);
    font-size: 34rpx;
  }
  ```

## 3. 组件开发规范

### 3.1 组件设计原则

- **单一职责**：每个组件只负责一个功能
- **高内聚低耦合**：组件内部逻辑完整，对外依赖最小
- **可复用性**：组件应该可以在多个场景中使用

### 3.2 组件通信规范

- **父传子**：使用 properties
  ```javascript
  // 子组件
  Component({
    properties: {
      recipe: {
        type: Object,
        value: {}
      },
      showAuthor: {
        type: Boolean,
        value: true
      }
    }
  });
  ```

- **子传父**：使用 triggerEvent
  ```javascript
  // 子组件
  methods: {
    onTap() {
      this.triggerEvent('tap', { recipeId: this.data.recipe.id });
    }
  }

  // 父组件 WXML
  <recipe-card recipe="{{item}}" bind:tap="onRecipeTap" />

  // 父组件 JS
  onRecipeTap(e) {
    const { recipeId } = e.detail;
    // 处理点击事件
  }
  ```

### 3.3 组件库使用规范

- **优先使用 vant-weapp 组件库**，能使用的就使用
- **常用组件**：
  - `van-button` - 按钮
  - `van-cell` - 单元格
  - `van-field` - 输入框
  - `van-popup` - 弹出层
  - `van-toast` - 轻提示
  - `van-dialog` - 对话框
  - `van-tab` - 标签页
  - `van-search` - 搜索框

- **自定义主题**：在 app.wxss 中覆盖 vant 的 CSS 变量
  ```css
  page {
    --button-primary-background-color: var(--color-primary);
    --button-primary-border-color: var(--color-primary);
  }
  ```

## 4. 云函数开发规范

### 4.1 云函数目录结构

**按功能模块组织云函数**，而不是每个接口一个文件夹：

```
APP/cloudfunctions/
├── user/                    # 用户模块
│   ├── index.js            # 路由入口
│   ├── login.js            # 登录
│   ├── updateInfo.js       # 更新信息
│   ├── search.js           # 搜索用户
│   ├── utils.js            # 工具函数
│   └── package.json
│
├── recipe/                  # 菜谱模块
│   ├── index.js            # 路由入口
│   ├── create.js           # 创建菜谱
│   ├── update.js           # 更新菜谱
│   ├── delete.js           # 删除菜谱
│   ├── getDetail.js        # 获取详情
│   ├── utils.js            # 工具函数
│   └── package.json
│
├── friend/                  # 好友模块
├── favorite/                # 收藏模块
└── enum/                    # 枚举模块
```

**优势**：
- ✅ 减少云函数数量（5个模块 vs 20+个独立函数）
- ✅ 简化部署流程
- ✅ 相关功能集中管理
- ✅ 便于代码复用

### 4.2 路由入口实现

每个模块的 `index.js` 作为路由入口：

```javascript
/**
 * 用户模块云函数
 *
 * 功能列表：
 * - login: 用户登录
 * - updateInfo: 更新用户信息
 * - search: 搜索用户
 *
 * 调用方式：
 * wx.cloud.callFunction({
 *   name: 'user',
 *   data: { action: 'login', ... }
 * })
 *
 * @module cloudfunctions/user
 * @author 作者名
 * @date 2026-02-05
 */

const cloud = require('wx-server-sdk');
cloud.init({ env: cloud.DYNAMIC_CURRENT_ENV });

// 动态路由映射
const handlers = {
  login: require('./login'),
  updateInfo: require('./updateInfo'),
  search: require('./search')
};

exports.main = async (event, context) => {
  const { action } = event;

  // 验证 action
  if (!action || !handlers[action]) {
    return {
      success: false,
      errorCode: 'INVALID_ACTION',
      errorMessage: `无效的操作: ${action}`
    };
  }

  try {
    // 调用对应的处理函数
    return await handlers[action].main(event, context);
  } catch (error) {
    console.error(`[user/${action}] 执行失败:`, error);
    return {
      success: false,
      errorCode: 'SYSTEM_ERROR',
      errorMessage: '系统错误'
    };
  }
};
```

### 4.3 具体功能文件实现

每个功能文件必须包含详细的文件头注释：

```javascript
/**
 * 用户登录
 *
 * 功能描述：
 * 1. 获取用户的 openid
 * 2. 查询用户是否已注册
 * 3. 首次登录时创建用户记录，生成唯一身份码
 * 4. 返回用户信息
 *
 * 业务逻辑：
 * - 首次登录：创建用户记录，生成 6-8 位身份码（字母+数字）
 * - 已注册用户：直接返回用户信息
 * - 身份码生成规则：大写字母+数字，需保证唯一性
 *
 * 参数：
 * @param {string} event.nickName - 用户昵称（首次登录必填）
 * @param {string} event.avatarUrl - 用户头像（首次登录必填）
 *
 * 返回：
 * @returns {Object} { success: true, data: { user, isFirstLogin } }
 *
 * 错误码：
 * - INVALID_PARAMS: 参数错误
 * - SYSTEM_ERROR: 系统错误
 *
 * @author 作者名
 * @date 2026-02-05
 */

const cloud = require('wx-server-sdk');
const db = cloud.database();

exports.main = async (event, context) => {
  const { nickName, avatarUrl } = event;
  const { OPENID } = cloud.getWXContext();

  try {
    // 1. 查询用户是否已存在
    const userResult = await db.collection('users')
      .where({ _openid: OPENID })
      .get();

    // 2. 已注册用户，直接返回
    if (userResult.data.length > 0) {
      return {
        success: true,
        data: {
          user: userResult.data[0],
          isFirstLogin: false
        }
      };
    }

    // 3. 首次登录，参数校验
    if (!nickName || !avatarUrl) {
      return {
        success: false,
        errorCode: 'INVALID_PARAMS',
        errorMessage: '首次登录需要提供昵称和头像'
      };
    }

    // 4. 生成唯一身份码
    const identityCode = await generateUniqueIdentityCode();

    // 5. 创建用户记录
    const createResult = await db.collection('users').add({
      data: {
        _openid: OPENID,
        nickName,
        avatarUrl,
        identityCode,
        bio: '',
        phone: '',
        isAdmin: false,
        recipeCount: 0,
        friendCount: 0,
        favoriteCount: 0,
        createTime: new Date()
      }
    });

    // 6. 返回新用户信息
    const newUser = await db.collection('users')
      .doc(createResult._id)
      .get();

    return {
      success: true,
      data: {
        user: newUser.data,
        isFirstLogin: true
      }
    };

  } catch (error) {
    console.error('[user/login] 登录失败:', error);
    return {
      success: false,
      errorCode: 'SYSTEM_ERROR',
      errorMessage: '系统错误'
```

### 4.4 模块内工具函数

每个云函数模块内创建 `utils.js` 存放工具函数：

```
cloudfunctions/
├── user/
│   ├── index.js            # 路由入口
│   ├── login.js            # 登录
│   ├── utils.js            # 工具函数
│   └── package.json
```

#### 工具函数实现

```javascript
// cloudfunctions/user/utils.js

/** 成功响应 */
exports.success = (data) => ({ success: true, data });

/** 错误响应 */
exports.error = (errorCode, errorMessage) => ({ success: false, errorCode, errorMessage });

/** 校验必填参数 */
exports.checkRequired = (params, fields) => {
  for (const field of fields) {
    if (params[field] === undefined || params[field] === null || params[field] === '') {
      return `缺少参数: ${field}`;
    }
  }
  return null;
};
```

#### 使用示例

```javascript
// cloudfunctions/user/login.js
const { success, error, checkRequired } = require('./utils');

exports.main = async (event, context) => {
  // 参数校验
  const err = checkRequired(event, ['nickName', 'avatarUrl']);
  if (err) return error('INVALID_PARAMS', err);

  try {
    // 业务逻辑...
    return success({ user, isFirstLogin: true });
  } catch (e) {
    console.error('[user/login] 失败:', e);
    return error('SYSTEM_ERROR', '系统错误');
  }
};
```

> **注意**：微信云函数不支持跨目录引用，每个云函数需要独立维护自己的工具函数。如果多个云函数需要相同的工具函数，可以复制一份到各自目录。

### 4.5 返回格式规范

所有云函数必须返回统一的格式：

```javascript
// 成功
{
  success: true,
  data: { /* 返回的数据 */ }
}

// 失败
{
  success: false,
  errorCode: 'ERROR_CODE',  // 错误码
  errorMessage: '错误描述'   // 错误信息
}
```

### 4.6 错误码规范

常用错误码：
- `INVALID_PARAMS` - 参数错误
- `INVALID_ACTION` - 无效的操作
- `NOT_FOUND` - 资源不存在
- `PERMISSION_DENIED` - 权限不足
- `ALREADY_EXISTS` - 资源已存在
- `SYSTEM_ERROR` - 系统错误

### 4.7 权限校验规范

- **必须校验用户身份**：使用 `cloud.getWXContext()` 获取 OPENID
- **必须校验操作权限**：确保用户有权限执行该操作
- **必须校验数据权限**：确保用户有权限访问该数据

```javascript
// 示例：删除菜谱时校验权限
const recipe = await db.collection('recipes').doc(recipeId).get();

if (recipe.data._openid !== OPENID) {
  return {
    success: false,
    errorCode: 'PERMISSION_DENIED',
    errorMessage: '无权删除该菜谱'
  };
}
```

## 5. 数据库操作规范

### 5.1 查询优化

- **使用索引**：为常用查询字段创建索引
  - `_openid` - 用户 ID（默认索引）
  - `status` - 菜谱状态
  - `isPublic` - 是否公开
  - `createTime` - 创建时间

- **限制返回字段**：只查询需要的字段
  ```javascript
  // 推荐
  const recipes = await db.collection('recipes')
    .field({
      name: true,
      images: true,
      authorName: true,
      favoriteCount: true
    })
    .get();

  // 不推荐（返回所有字段）
  const recipes = await db.collection('recipes').get();
  ```

- **分页查询**：避免一次性查询大量数据
  ```javascript
  const PAGE_SIZE = 20;
  const recipes = await db.collection('recipes')
    .skip(page * PAGE_SIZE)
    .limit(PAGE_SIZE)
    .get();
  ```

### 5.2 数据一致性

- **使用事务**：确保多个操作的原子性
  ```javascript
  // 示例：收藏菜谱时，同时更新多个计数
  const transaction = await db.startTransaction();

  try {
    // 1. 创建收藏记录
    await transaction.collection('favorites').add({
      data: {
        _openid: OPENID,
        recipeId,
        recipeOpenid,
        createTime: new Date()
      }
    });

    // 2. 更新菜谱的收藏数
    await transaction.collection('recipes').doc(recipeId).update({
      data: {
        favoriteCount: db.command.inc(1)
      }
    });

    // 3. 更新创建者的获得收藏数
    await transaction.collection('users').where({
      _openid: recipeOpenid
    }).update({
      data: {
        favoriteCount: db.command.inc(1)
      }
    });

    await transaction.commit();
  } catch (error) {
    await transaction.rollback();
    throw error;
  }
  ```

### 5.3 软删除规范

- **不要真正删除数据**，使用软删除标记
  ```javascript
  // 推荐：软删除
  await db.collection('recipes').doc(recipeId).update({
    data: {
      isDeleted: true,
      deleteTime: new Date()
    }
  });

  // 不推荐：硬删除
  await db.collection('recipes').doc(recipeId).remove();
  ```

- **查询时过滤已删除数据**
  ```javascript
  const recipes = await db.collection('recipes')
    .where({
      isDeleted: db.command.neq(true)  // 或者 isDeleted: false
    })
    .get();
  ```

- **后端校验**：云函数必须进行数据校验，不能信任前端传入的数据

```javascript
// 云函数中的参数校验
function validateRecipeData(data) {
  if (!data.name || data.name.trim().length === 0) {

  }

  if (data.name.length > 50) {

}
```

## 附录：常用工具函数

### A.1 时间格式化

```javascript
/**
 * 格式化时间
 * @param {Date} date - 日期对象
 * @param {string} format - 格式，如 'YYYY-MM-DD HH:mm:ss'
 * @returns {string} 格式化后的时间字符串
 */
function formatTime(date, format = 'YYYY-MM-DD HH:mm:ss') {
  const year = date.getFullYear();
  const month = String(date.getMonth() + 1).padStart(2, '0');
  const day = String(date.getDate()).padStart(2, '0');
  const hour = String(date.getHours()).padStart(2, '0');
  const minute = String(date.getMinutes()).padStart(2, '0');
  const second = String(date.getSeconds()).padStart(2, '0');

  return format
    .replace('YYYY', year)
    .replace('MM', month)
    .replace('DD', day)
    .replace('HH', hour)
    .replace('mm', minute)
    .replace('ss', second);
}
```

### A.2 图片上传

```javascript
 * 上传图片到云存储
```

### A.3 防抖函数

```javascript
/**
 * 防抖函数
 * @param {Function} func - 要执行的函数
 * @param {number} wait - 等待时间（毫秒）
 * @returns {Function} 防抖后的函数
 */
function debounce(func, wait = 300) {
  let timeout;
  return function(...args) {
    clearTimeout(timeout);
    timeout = setTimeout(() => {
      func.apply(this, args);
    }, wait);
  };
}
```
