## 🎯 核心原则

### 1. 项目结构
- 页面/组件文件夹：小写字母 + 短横线，如 `recipe-detail`
- 云函数：小驼峰命名，如 `getRecipeDetail`
- 每个页面/组件必须包含 4 个文件：`.js`、`.wxml`、`.wxss`、`.json`

### 2. 代码风格

**JavaScript**
- 变量/函数：小驼峰 `userName`、`getRecipeDetail()`
- 常量：全大写 + 下划线 `MAX_IMAGE_COUNT`
- 优先使用 `async/await`，必须用 `try-catch` 处理错误
- `setData` 只更新变化的数据，避免频繁调用

**WXML**
- 避免嵌套过深（不超过 5 层），使用精简的方式实现
- 列表渲染必须指定 `wx:key`
- 优先使用 `wx:if`，而非 `hidden`（除非需要频繁切换）

**WXSS**
- 必须使用 CSS 变量，不要硬编码颜色/间距
- 使用 BEM 命名：`.recipe-card__title`
- 优先使用 class 选择器

### 3. 组件开发
- **优先使用 vant-weapp 组件库**，能用就用
- 父传子用 `properties`，子传父用 `triggerEvent`
- 组件要单一职责、可复用

### 4. 云函数

**目录结构**：按功能模块组织（user/、recipe/、friend/、favorite/、enum/）

**模块内工具函数**：每个云函数模块内创建 `utils.js` 存放工具函数
```
cloudfunctions/
├── user/
│   ├── index.js         # 路由入口
│   ├── login.js         # 登录功能
│   ├── updateInfo.js    # 更新信息
│   ├── utils.js         # 工具函数
│   └── package.json
```

> **注意**：微信云函数不支持跨目录引用，每个云函数需要独立维护自己的工具函数。

**工具函数示例**：
```javascript
// cloudfunctions/user/utils.js
exports.success = (data) => ({ success: true, data });
exports.error = (errorCode, errorMessage) => ({ success: false, errorCode, errorMessage });
exports.checkRequired = (params, fields) => {
  for (const field of fields) {
    if (!params[field]) return `缺少参数: ${field}`;
  }
  return null;
};
```

**路由入口**（index.js）：
```javascript
/**
 * 用户模块云函数
 *
 * 功能列表：
 * - login: 用户登录
 * - updateInfo: 更新用户信息
 * - search: 搜索用户
 */
const cloud = require('wx-server-sdk');
cloud.init({ env: cloud.DYNAMIC_CURRENT_ENV });

const handlers = {
  login: require('./login'),
  updateInfo: require('./updateInfo'),
  search: require('./search')
};

exports.main = async (event, context) => {
  const { action } = event;
  if (!action || !handlers[action]) {
    return { success: false, errorCode: 'INVALID_ACTION', errorMessage: `无效的操作: ${action}` };
  }
  try {
    return await handlers[action].main(event, context);
  } catch (error) {
    console.error(`[user/${action}] 执行失败:`, error);
    return { success: false, errorCode: 'SYSTEM_ERROR', errorMessage: '系统错误' };
  }
};
```

**功能文件**：必须包含详细的文件头注释
```javascript
/**
 * 用户登录
 *
 * 功能描述：
 * 1. 获取用户的 openid
 * 2. 查询用户是否已注册
 * 3. 首次登录时创建用户记录，生成唯一身份码
 * 4. 返回用户信息
 *
 * 业务逻辑：
 * - 首次登录：创建用户记录，生成 6-8 位身份码（字母+数字）
 * - 已注册用户：直接返回用户信息
 * - 身份码生成规则：大写字母+数字，需保证唯一性
 *
 * 数据库操作：
 * - 查询 users 表
 * - 插入 users 表（首次登录）
 *
 * 参数：
 * @param {string} event.nickName - 用户昵称（首次登录必填）
 * @param {string} event.avatarUrl - 用户头像（首次登录必填）
 *
 * 返回：
 * @returns {Object} { success: true, data: { user, isFirstLogin } }
 *
 * 错误码：
 * - INVALID_PARAMS: 参数错误
 * - SYSTEM_ERROR: 系统错误
 *
 * @author 作者名
 * @date 2026-02-05
 */
const cloud = require('wx-server-sdk');
const db = cloud.database();

exports.main = async (event, context) => {
  const { nickName, avatarUrl } = event;
  const { OPENID } = cloud.getWXContext();

  try {
    // 业务逻辑实现...
  } catch (error) {
    console.error('[user/login] 登录失败:', error);
    return { success: false, errorCode: 'SYSTEM_ERROR', errorMessage: '系统错误' };
  }
};
```

**统一返回格式**：
```javascript
// 成功
{ success: true, data: { /* 返回的数据 */ } }

// 失败
{ success: false, errorCode: 'ERROR_CODE', errorMessage: '错误描述' }
```

**常用错误码**：
- `INVALID_PARAMS` - 参数错误
- `INVALID_ACTION` - 无效的操作
- `NOT_FOUND` - 资源不存在
- `PERMISSION_DENIED` - 权限不足
- `ALREADY_EXISTS` - 资源已存在
- `SYSTEM_ERROR` - 系统错误

**必须校验**：参数校验、权限校验、数据权限

### 5. 数据库操作
- 使用软删除（`isDeleted: true`），不要硬删除数据
- 查询时限制返回字段（使用 `field()`），使用分页加载
- 多个操作用事务保证数据一致性
- 为常用查询字段创建索引（`_openid`、`status`、`isPublic`、`createTime`）

### 6. 性能优化
- 图片压缩后上传（`wx.compressImage`），列表图片使用懒加载（`lazy-load="{{true}}"`）
- 用户信息缓存到本地（`wx.getStorageSync`/`wx.setStorageSync`）
- 列表实现分页加载（`skip`/`limit`）和下拉刷新（`onPullDownRefresh`）
- 避免频繁调用 `setData`，批量更新数据

### 7. 安全规范
- 前后端都要校验数据（前端提升体验，后端保证安全）
- 云函数必须校验权限（使用 `cloud.getWXContext()` 获取 OPENID）
- 不要在前端存储敏感信息（密码、token 等）
- 敏感操作需要二次确认（删除、发布等）

### 8. UI 开发
- 页面背景使用 `--bg-color` (#FAFAF8)，不要用纯白
- 卡片圆角 `--radius-lg` (24rpx)，阴影 `--shadow-level-1`
- 去线化设计：用间距和背景色块区分内容，避免使用横线边框
- 可点击区域添加 `hover-class` 效果
- 数据为空时展示友好的提示

### 9. Git 提交
- 格式：`<type>(<scope>): <subject>`
- type: `feat`（新功能）/`fix`（修复）/`docs`（文档）/`style`（格式）/`refactor`（重构）/`perf`（性能优化）
- 小步提交，提交前测试，避免大批量提交
