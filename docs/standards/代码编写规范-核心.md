## 🎯 核心原则

### 1. 项目结构
- 页面/组件文件夹：小写字母 + 短横线，如 `recipe-detail`
- 云函数：小驼峰命名，如 `getRecipeDetail`
- 每个页面/组件必须包含 4 个文件：`.js`、`.wxml`、`.wxss`、`.json`

### 2. 代码风格

**JavaScript**
- 变量/函数：小驼峰 `userName`、`getRecipeDetail()`
- 常量：全大写 + 下划线 `MAX_IMAGE_COUNT`
- 优先使用 `async/await`，必须用 `try-catch` 处理错误
- `setData` 只更新变化的数据，避免频繁调用

**WXML**
- 避免嵌套过深（不超过 5 层）
- 列表渲染必须指定 `wx:key`
- 优先使用 `wx:if`，而非 `hidden`

**WXSS**
- 必须使用 CSS 变量，不要硬编码颜色/间距
- 使用 BEM 命名：`.recipe-card__title`
- 优先使用 class 选择器

### 3. 组件开发
- **优先使用 vant-weapp 组件库**，能用就用
- 父传子用 `properties`，子传父用 `triggerEvent`
- 组件要单一职责、可复用

### 4. 云函数

**目录结构**：按功能模块组织（user/、recipe/、friend/、favorite/、enum/）

**公共模块**：创建 `common/` 模块，供所有云函数共享
```
cloudfunctions/
├── common/              # 公共模块
│   ├── utils/
│   │   ├── response.js # 统一响应格式
│   │   ├── validate.js # 参数校验
│   │   └── error.js    # 错误码定义
│   └── package.json
├── user/
│   └── package.json    # "common": "file:../common"
```

**使用公共模块**：
```javascript
const { success, error, errorCodes } = require('common');

return success({ user });
return error(errorCodes.INVALID_PARAMS, '参数错误');
```

**路由入口**（index.js）：
```javascript
const handlers = {
  login: require('./login'),
  updateInfo: require('./updateInfo')
};

exports.main = async (event, context) => {
  const { action } = event;
  if (!handlers[action]) {
    return { success: false, errorCode: 'INVALID_ACTION' };
  }
  return await handlers[action].main(event, context);
};
```

**功能文件**：必须包含详细的文件头注释
```javascript
/**
 * 用户登录
 *
 * 功能描述：
 * 1. 获取用户的 openid
 * 2. 查询用户是否已注册
 * 3. 首次登录时创建用户记录
 *
 * 业务逻辑：
 * - 首次登录：创建用户记录，生成身份码
 * - 已注册用户：直接返回用户信息
 *
 * 参数：
 * @param {string} event.nickName - 用户昵称
 * @param {string} event.avatarUrl - 用户头像
 *
 * 返回：
 * @returns {Object} { success, data }
 *
 * 错误码：
 * - INVALID_PARAMS: 参数错误
 * - SYSTEM_ERROR: 系统错误
 */
```

**统一返回格式**：`{ success: true/false, data/errorCode/errorMessage }`

**必须校验**：参数校验、权限校验

### 5. 数据库操作
- 使用软删除（`isDeleted: true`），不要硬删除
- 查询时限制返回字段，使用分页
- 多个操作用事务保证一致性

### 6. 性能优化
- 图片压缩后上传，列表图片使用懒加载
- 枚举值缓存到本地
- 列表实现分页加载和下拉刷新

### 7. 安全规范
- 前后端都要校验数据
- 云函数必须校验权限
- 不要在前端存储敏感信息

### 8. UI 开发
- 页面背景使用 `--bg-color` (#FAFAF8)，不要用纯白
- 卡片圆角 `--radius-lg` (24rpx)
- 去线化设计：用间距和背景色块区分内容
- 可点击区域添加 `hover-class` 效果

### 9. Git 提交
- 格式：`<type>(<scope>): <subject>`
- type: `feat`/`fix`/`docs`/`style`/`refactor`/`perf`
- 小步提交，提交前测试
